# Evaluation Report: Baseline RAG vs. Hybrid RAG + LoRA

**Question this report answers:** does adding a locally trained LoRA adapter to
the Northstar RAG assistant improve held-out behaviour enough to justify training,
deploying and maintaining it?

**Short answer: revise, do not deploy yet.** The adapter turns a baseline that
serves *nothing* (every answer fails citation validation) into one that serves
half of the answerable questions. However, most of the gain comes from learning
the `[source-id]` citation format, not from better understanding of the
policies. The adapter also made abstention worse: it answered two questions
that should have been escalated. A cheaper fix for the citation format has not
been ruled out yet (see [Next experiments](#prioritized-next-experiments)).

All numbers come from one real run (`uv run python -m src evaluate`). Full
tables are in [benchmark_results.md](benchmark_results.md), and raw model text
is in `benchmark_trace.json`, which is git-ignored and regenerated by that
command.

The training data is unchanged from the supplied file. Validation found no
duplicate IDs, no unknown source IDs, and no evaluation questions copied into
training. Some *scenarios* overlap with training (for example, "partial annual
refund after 45 days"), so this is a within-domain test, not proof of
generalization to new policies.

## 2. Retrieval Quality (shared by both systems)

| Metric | Value |
| --- | ---: |
| Recall@3 (answerable cases) | **1.000** (10/10) |
| Mean reciprocal rank | **1.000** (correct policy ranked first every time) |
| Weakest top score, answerable | 0.525 (`eval-duplicate-payment`) |
| Strongest top score, unanswerable | 0.662 (`eval-bank-chargeback`) |

Retrieval is **not** the bottleneck for answerable questions. Every failure on
those 10 cases happens after the right evidence was already in the prompt.

### Threshold evidence

The threshold `0.30` was set *before* the benchmark, from the hypothesis "a
top cosine score below 0.30 means the question is off-topic". The sweep below
is a diagnostic. It was not used to choose a threshold, because picking the
best threshold on the exam cases and then reporting that score would leak the
test into the design.

| Threshold | Answerable kept | Unanswerable blocked |
| ---: | ---: | ---: |
| 0.30 (chosen) | 10/10 | 2/4 |
| 0.50 | 10/10 | 2/4 |
| 0.55 | 9/10 | 3/4 |
| 0.70 | 5/10 | 4/4 |

The scores overlap: the bank-chargeback question (0.662) scores higher than
five answerable questions. **No similarity threshold can separate these
cases.** "Sounds related to a policy" is not the same as "is answered by a
policy". The threshold reliably catches only off-topic questions (cafeteria
0.13, bicycle 0.21). Near-domain unanswerable questions must be caught by the
model saying "insufficient", or by an extra answerability check.

## 3. Answer Quality

| System | Relevance | Raw coverage¹ | Faithfulness² | Style² | Decision accuracy | Answered (of 10 answerable) | Abstained (of 4 unanswerable) | Rejected | Latency (s/answer) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| base-only (bonus) | 0.000 | 0.000 | 0.000 (0/13) | 0.981 | 0.786 | 10 | 1 | 0 | 1.51 |
| **rag-base** (baseline) | **0.000** | 0.550 | n/a (0 served) | n/a | **0.214** | **0** | 3 | **11** | 1.92 |
| **rag-lora** (hybrid) | **0.350** | 0.650 | 0.714 (5/7) | 1.000 | **0.500** | **5** | 2 | **5** | 1.84 |
| hybrid − baseline | +0.350 | +0.100 | n/a | n/a | +0.286 | +5 | **−1** | −6 | −0.08 |

¹ *Raw coverage* applies the required-term check to what the model wrote
**before** citation validation. It separates "knew the facts" from "formatted
the citation". It is a diagnostic only; rejected text is never shown to customers.
² Faithfulness and style are measured only on answers that were actually served.

How to read the metrics:

- **Relevance** is the share of the case's required terms found in the served
  answer. Abstained or rejected answers score 0.
- **Faithfulness** asks: of the served answers, how many cite only the expected
  policy and contain no forbidden claim? Answering an unanswerable question
  always counts as unfaithful.
- **Style** checks four things: a direct first sentence (≤ 25 words), ≤ 60
  words in total, no hedge words, and no repeated sentences.
- **Decision accuracy** asks: did the system answer when it should, and abstain
  when it should?

### Why base-only has the "best" decision accuracy (and why that is misleading)

`base-only` answers every question, and 10 of the 14 cases are answerable, so
it scores 0.786 by default. Its answers are mostly invented. Examples: *"standard
shipping … is typically 2-3 weeks"* (the policy says 3–5 business days), and a
log-security answer that repeats "no, no, no…" for 80 tokens. Decision accuracy
measures *whether* a system answers, not whether the answer is right. This
bonus row shows what retrieval adds: without evidence, relevance and
faithfulness are both 0.

than the baseline.

## 5. Failure and Fragile-Success Analysis

1. **Baseline: citation format, not knowledge, is the blocker (11 rejections).**
   The base model never wrote a `[source-id]` citation, so the validator
   rejected every generated answer. Its raw coverage (0.55) shows it often
   *did* read the evidence: `pause` and `outage-updates` are correct but
   uncited. Two raw answers contradict the evidence (`packed-address`,
   `log-secrets`: "Yes, …"). Here, validation protected customers.

2. **Hybrid: the gain is mostly formatting.** Served relevance rose by +0.35,
   but raw coverage rose only by +0.10. Most of the improvement is that 5
   answers now pass citation validation. Two correct hybrid answers
   (`packed-address`, `outage-updates`) were still rejected because the
   citation was missing. So the format lesson was learned only partly.

3. **Hybrid: worse abstention on near-domain questions (regression).** Both
   near-domain unanswerable questions pass the 0.30 threshold (scores 0.66
   and 0.55). The hybrid then answered both with invented facts that cite a
   real policy. The citation validator cannot catch this, because the cited
   source *was* retrieved. Only 1 of the 16 training examples teaches
   abstention, so the adapter learned "always answer and cite". This is the
   most important risk, because the output looks trustworthy.

4. **Fragile success: the baseline's correct abstention was accidental.** On
   `bank-chargeback`, the baseline wrote "The answer is: 24 hours", but the
   same text contained the fallback phrase, so the abstention detector
   counted it. A slightly different wording would have produced a wrong
   answer.

5. **Fragile success: the faithfulness proxy passes a wrong answer.** On
   `pause`, the hybrid cites `[subscriptions]` and avoids forbidden phrases, so
   it counts as "faithful". But it describes cancellation, not pausing.
   Relevance (0.0) caught it; faithfulness did not. The proxy checks *where*
   a claim points, not *whether* it is true.

6. **Lexical rubric misses.** `annual-refund` is correct but gets relevance
   0.5, because "cannot" does not whole-word-match the required term "not".
   The baseline's wrong `log-secrets` answer gets raw coverage 1.0, because it
   *quotes* "must not include … authentication tokens" right after concluding
   "Yes". Word matching cannot read negation. This is why every case was
   also checked by hand.

## 6. Cost Considerations

| | Baseline RAG | Hybrid RAG + LoRA |
| --- | --- | --- |
| Training | none | 71 s CPU per run, plus retraining whenever training data, base model or prompt format change |
| Artifacts to version | none | 1.9 MB adapter + provenance file (training-data hash, base revision) |
| Inference memory | base model (~540 MB fp32) | same base + 1.9 MB adapter (could be merged into the weights) |
| Latency | 1.92 s/answer | 1.84 s/answer (shorter answers offset adapter overhead) |
| Maintenance risk | prompt changes take effect immediately | prompt or base-model changes silently invalidate the adapter; the code refuses a stale adapter, which forces retraining |

At this scale, compute is cheap. The real cost is **process**: curating
training examples, keeping them separate from evaluation, re-running the
benchmark after every retrain, and guarding against regressions like the
abstention failure. "Only 0.34 % of parameters train" does not mean 0.34 % of
the compute: the frozen 135M-parameter model still runs forward and backward
on every step. Peak memory and energy were not measured.

## 7. Answers to the Required Questions

**1. Which held-out behaviours changed after loading the adapter?**
Citation behaviour changed most: answers passing validation went from 0/14 to
7/14. Answers became short and direct (style 1.0 on served answers; the
baseline produced long lists and commentary). Abstention changed for the
worse: near-domain unanswerable questions went from "declined or rejected" to
"confident cited hallucination", and correctly abstained unanswerable cases
dropped from 3/4 to 2/4. Latency was essentially unchanged.

**2. Did the adapter improve evidence use, style, both, or neither?**
**Style clearly; evidence use only slightly.** Style and citation format
improved a lot. Evidence use (raw coverage of required facts before
validation) improved only from 0.55 to 0.65. The manual review is mixed: the
hybrid fixed `standard-shipping` and `annual-refund`, but broke `pause` and
`passport`, which the baseline had right in substance.

**3. Which retrieval errors limit both systems regardless of fine-tuning?**
Ranking is not the problem (recall@3 = MRR = 1.0). The limit is that
**similarity is not answerability**. The two near-domain unanswerable
questions (bank chargeback 0.662, shipping compensation 0.549) score above the
threshold and above several answerable questions. Both systems therefore
receive plausible but non-answering evidence. Each threshold that blocks them
also blocks real questions (at 0.70, only 5/10 answerable questions are kept).
Each top-3 also includes weaker chunks (for example `response-style`,
`incidents`) that a small model can mix into its answer, as the hybrid did on
`authenticator` and `log-secrets`.

**4. Does the measured improvement justify adapter training and maintenance?**
**Not yet.** Training is cheap (71 s, 1.9 MB). Even so, the measured benefit
is mainly a citation-format habit that a cheaper method might deliver. That
benefit comes with a safety regression on unanswerable questions, and it rests
on 14 cases from one training seed, so a single case moves decision accuracy
by 7 percentage points. The recommendation is to **revise**: keep the adapter
as an experiment and do not ship it.

**5. What experiment would most reduce uncertainty in that decision?**
Give the **baseline** one in-context example of a cited answer and one of an
abstention (prompt-only, no training). Rerun both systems on an expanded
held-out set with more near-domain unanswerable questions. If the prompted
baseline matches the hybrid's citation pass rate, the adapter has no
remaining justification. If the hybrid still wins on content and style after
its training data gains more abstention examples, keeping it is justified.

## 8. Recommendation

**Revise the hybrid design; do not replace the baseline with it yet.**

- *Keep:* the shared retriever, the threshold for off-topic questions, and the
  citation validator. The validator blocked every contradicting answer
  (`packed-address`, `log-secrets`) from both systems.
- *Revise:* add roughly 4–6 abstention examples (near-domain questions whose
  context does not answer them) to the training data, add examples that
  always end with a citation, and retrain with 3 seeds to measure variance.
- *Reject (for now):* serving hybrid answers to near-domain questions without
  an extra answerability check.

## Prioritized Next Experiments

1. **Prompt-only citation baseline** (cheapest alternative): add one cited
   example and one abstention example to the baseline prompt, and compare.
2. **Abstention-aware training data:** add near-domain "insufficient" examples
   (written fresh, not copied from the evaluation set) and re-measure
   correctly abstained unanswerable cases.
3. **Bigger held-out set + seed variance:** about 40 cases, including
   paraphrases and policy-change cases, and 3 training seeds, to report a
   range instead of one number.
4. **Answerability check:** a second-stage check (for example a cross-encoder
   reranker, or the model asked "does the context answer this?") before
   generation, evaluated as a separate metric.
5. **Stronger small base model** (for example a 360M–1.7B instruct model) under
   the same retriever and rubric, to see whether the format problem
   disappears without fine-tuning.
